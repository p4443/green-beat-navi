## 1. 企画概要

### 1-1. コンセプト

「GREEN BEAT NAVI」は、森林公園駅から森林公園緑道を歩きながら、音楽、地域の食、楽器体験をめぐる回遊型イベント案内PWAです。

**企画メッセージ：森林公園駅から緑道へ。音楽と地域の魅力を歩いてつなぐ。**

### 1-2. 企画目的

1. 音楽をきっかけに緑道の往復利用を促す。
2. 地域演奏者、飲食・物産、楽器体験の接点をつくる。
3. スマートフォン案内で移動、時刻、混雑を把握しやすくする。
4. デジタルスタンプで回遊と行動データ活用の実証を行う。
5. 2027年開催に向けた関係者説明・プレゼンの共通資料とする。

1. 駅北口で案内を確認し、QRから参加開始。
2. STARTスタンプと匿名参加IDを取得。

### 2-4. 回遊企画

**GREENWAY CHALLENGE**

- 参加費：無料（デモ）
- 距離：約5.8km往復
- 所要目安：歩行だけで約60～90分程度を想定。ただし演奏鑑賞等で延長
- スタンプ：4地点
- 特典：4地点達成時にデモ画面でコード `GREENBEAT-2027` を表示

### 3-3. データ保存

- 来場者データはブラウザlocalStorageへ保存。
- 運営データもブラウザlocalStorageへ保存。
- 同じブラウザプロファイルのタブ間ではstorage eventによって運営状態を同期。
- 別端末、別ブラウザ、別プロファイル、プライベートブラウズ間では同期しない。
- サイトデータ削除またはブラウザ変更で参加履歴が消える。

### 3-4. 管理者認証

`/admin` は GitHub OAuth による個人アカウント認証+許可リスト+4ロール(全体管理/プログラム担当/出店担当/閲覧)を実装済みです。認証用環境変数が未設定のローカルデモでは、従来どおり認証なしで動作します(GBN-DEP-001 6章)。

本番運用では引き続き次を満たします。

- 個人アカウントまたはSSO
- 最小権限（全体管理、プログラム担当、出店担当、閲覧）
- セッション期限、再認証、ログアウト
- 操作履歴、変更理由、監査ログ
- 緊急時の管理者引継ぎ
- 秘密情報を印刷物・ソースコード・配布URLへ含めない運用

印刷用の端末認証欄は「操作マニュアル」末尾に設け、当日担当者のみが回収・廃棄します。

## 4. 運営体制

### 4-1. 関係主体

| 主体 | 主な役割 |
| :--- | :--- |
| 主催・企画責任 | 企画決定、関係者調整、広報承認、最終判断 |
| 指定管理者 | 現地使用、安全、施設運営調整 |
| 会場責任者 | 開催判断、現場統括、緊急連絡 |
| イベント統括 | 全体進行、タイムテーブル、出演・出店調整 |
| 情報・アプリ担当 | デモ起動、QR、告知、運行・混雑更新 |
| 演奏担当 | 出演者受付、転換、音響、フィナーレ |
| 出店・体験担当 | 搬入、衛生、在庫、顧客対応 |
| 安全・警備担当 | 歩行動線、救護、混雑、天候、避難 |
| 広報担当 | 公式表現、案内、問い合わせ、取材 |

### 4-2. 運営判断

| 判断 | 一次担当 | 最終承認 |
| :--- | :--- | :--- |
| プログラム開始・遅延・中止 | イベント統括 | 会場責任者 |
| 緊急告知配信 | 情報担当 | 会場責任者 |
| 出店休止・売切れ | 出店担当 | イベント統括 |
| 安全上の通行停止 | 安全担当 | 会場責任者 |
| 開催中止・縮小 | 会場責任者・主催 | 事前に定めた権限者 |

### 4-3. 推奨配置（要検討）

- 森林公園駅北口：総合案内1、受付1、アプリ/QR1、誘導2以上、救護・連絡体制
- 木陰・演奏地点：舞台責任1、転換・誘導
- 体験地点：体験案内、楽器・衛生・安全監視
- 出店地点：各店舗責任者、食品衛生責任
- 南口折返し：誘導、QR案内、距離・復路説明
- 移動巡回：コース上の安全確認、迷子・体調不良対応

人数・資格・消防・警備要件は未確定です。現地調査と関係機関協議で確定します。

## 5. 開催前・当日・終了後

### 5-1. 事前準備

1. 主催、管理、出演、出店、保険、許認可の責任分界を合意。
2. 現地座標、動線、屋外電源、避難路、救護位置を実測。
3. 雨天・暑熱・強風・雷・濃霧・地震等の基準を承認。
4. 日程、プログラム、出演者、店舗、価格、特典を確定。
5. QR公開URL、TLS、本番認証、バックアップ端末を準備。
6. 同一ブラウザでの管理表示試験と実スマートフォン試験を実施。
7. QR印刷物の場所、設置高さ、視認性、予備枚数を確認。
8. 問い合わせ窓口と緊急連絡網を作成。

### 5-3. デモ判定

最低限、次を確認してから開始します。

- ホーム、マップ、時刻表、出店、参加、スタンプを表示できる。
- `/admin` の変更が同一ブラウザの別タブに反映される。
- QRが実スマートフォンから接続できる。
- STARTから4地点を一周できる。
- 誤配布URL、仮の管理者PW、個人情報が画面にない。

## 6. 情報更新・告知

### 6-1. 運営変更の種類

| 種別 | 操作 | 反映範囲 |
| :--- | :--- | :--- |
| 全体告知 | ご案内／注意／緊急 | 同一ブラウザの来場者画面 |
| プログラム | 予定どおり／遅延10–30分／中止 | 同一ブラウザのタイムテーブル |
| スポット | 営業中／休止／売切れ | 同一ブラウザの出店・マップ |
| 混雑 | 空いている／やや混雑／混雑 | 同一ブラウザの出店・マップ |

### 6-2. 緊急時

1. 現場の安全確保をアプリ操作より優先。
2. 会場責任者の指示を確認。
3. 緊急告知は、場所・対象・行動を簡潔に記載。
4. 音声、掲示、SNS等のほかの手段でも同じ内容を伝える。
5. 現行アプリは別端末へ自動反映されないため、掲示・放送で補完。
6. 警察、消防、救急、施設側への連絡基準は事前に定める。

## 7. 安全・アクセシビリティ・個人情報

### 7-1. 参加者へ必ず周知する事項

- 歩行中は画面を操作せず、立ち止まって確認する。
- コース、横断、開放時間、退避場所の案内に従う。
- 天候・体調・歩行距離に応じて中止できる。
- 車椅子・ベビーカー利用者向け経路、勾配、休憩場所を事前確認する。
- 楽器体験は衛生、共有器具、年齢、保護者同伴の条件を定める。

### 7-2. アクセシビリティ

- 文字サイズ・色コントラスト・タップ領域を検証。
- 緊急情報を色だけでなく「注意」「緊急」等の文字でも示す。
- 地図以外のテキスト説明を提供。
- スクリーンリーダー、キーボード操作、拡大表示を本番受入試験へ含める。

### 7-3. 個人情報

- 現行参加IDは匿名IDで、氏名・電話・メールを入力しない。
- 実運用で分析・同意・クーポン連携を行う場合、利用目的、保持期間、第三者提供、問い合わせ先を明示。
- 運営画面・認証情報・参加端末の画面を撮影共有しない。
