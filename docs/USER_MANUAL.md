- 文書番号：GBN-MAN-001
- 版:1.2

- 対象：GREEN BEAT NAVI デモ・プレゼン用MVP

## 1. デモ開始前の確認

### 1-1. 必須事項

| 項目 | 確認内容 |
| :--- | :--- |
| Docker Desktop | 起動し、緑色の正常稼働状態であること |
| Docker Compose | プロジェクトの `compose.yaml` を利用できること |
| 表示端末 | Chrome、Safari、Edge等の現行ブラウザが利用できること |
| ネットワーク | 地図表示にはインターネット接続が必要 |
| 公開URL | スマートフォンにも見せる場合、`localhost` ではなく表示PCのLAN IP等を利用 |
| 音量・画面 | プレゼン用端末の音量、画面明るさ、充電状態 |

### 1-2. 認証・秘密情報

ローカルデモ(認証用環境変数が未設定)の `/admin` はログイン不要で動作します。**管理画面用パスワードは不要です。** 本番公開時は GitHub アカウントによるログインが必要になります(GBN-DEP-001 6章)。

## 2. デモの起動・停止

### 2-1. 起動

1. Docker Desktopを起動します。
2. VS Codeまたはターミナルでプロジェクトフォルダを開きます。
3. 次を実行します。

```bash
docker compose up
```

4. 起動完了後、ブラウザで `http://localhost:3000` を開きます。
5. 次のURLを順に開き、表示と操作を確認します。

| 画面 | URL | 確認ポイント |
| :--- | :--- | :--- |
| ホーム | `/` | 企画情報と各導線 |
| 会場マップ | `/map` | ルート、マーカー、ポップアップ |
| タイムテーブル | `/schedule` | プログラムと運行状態 |
| 出店 | `/spots` | 営業・混雑状態 |
| スタンプ | `/stamps` | 参加未開始の表示 |
| QR | `/qr-demo` | 4種類のURLとQR |
| 運営 | `/admin` | 状態管理・告知・リセット |

初回起動や依存関係再作成時は時間がかかる場合があります。画面が接続できない場合は、Docker Desktopとターミナルのエラー表示を確認してください。

### 2-2. バックグラウンド起動

ターミナルを占有せず起動する場合：

```bash
docker compose up -d
```

終了：

```bash
docker compose down
```

再起動：

```bash
docker compose restart
```

ログ確認：

```bash
docker compose logs -f
```

### 2-3. スマートフォンを利用する場合

1. 表示PCとスマートフォンを同じLANに接続します。
2. 表示PCのLAN IPを確認し、スマートフォンで `http://＜PCのIP＞:3000` を開きます。
3. `/qr-demo` をそのLAN URLで開くと、QRは同じ公開元URLを使用します。
4. QRを実際に読み取り、参加開始からチェックインまで試験します。
5. `NEXT_PUBLIC_APP_URL` を利用する場合は、スキームを含む公開URLを設定して起動します。

> `http://localhost:3000` を表したQRは、読み取ったスマートフォン自身を指します。PCのみのデモ以外ではそのまま配布しないでください。

## 3. 来場者向け操作

### 3-1. 画面一覧

| 画面 | 対象 | 主な操作 |
| :--- | :--- | :--- |
| `/` ホーム | 来場者 | 開催概要、見どころ、各機能への移動 |
| `/map` 会場マップ | 来場者 | ルートとスポット確認、マーカー選択 |
| `/schedule` タイムテーブル | 来場者 | 開催状況確認、プログラムのお気に入り |
| `/spots` お店とメニュー | 来場者 | 営業・混雑確認、スポットのお気に入り |
| `/join` 参加開始 | 来場者 | 注意事項確認、匿名参加ID発行、START付与 |
| `/stamps` スタンプ | 来場者 | 進捗、デモチェックイン、クーポン表示 |
| `/checkin/地点ID` | 来場者 | QR読み取り後のスタンプ取得 |

### 3-2. 会場マップ

- 緑色ラインは往路、オレンジ色ラインは復路の表示です。
- マーカーを選ぶと、スポット名、説明、営業・混雑状況を表示します。
- 起終点は確認済み、中間スポット座標はプレゼン用の仮位置です。
- 地図タイルはOpenStreetMapから取得するため、オフライン時は地図画像を表示できない場合があります。

### 3-3. お気に入り

- タイムテーブルまたは出店の `☆` を選ぶと `★` に変わります。
- 再度選ぶと解除されます。
- 情報は同じ端末・同じブラウザのlocalStorageに保存されます。

### 3-4. スタンプラリー

#### 参加開始

1. `/join` を開きます。
2. 「参加する」→内容を確認します。
3. 「企画内容と注意事項を確認しました」を選択します。
4. 「確認して参加開始」を選びます。
5. `GB-` から始まる匿名参加IDとSTARTスタンプが保存され、会場マップへ移動します。

#### チェックポイント

| 順 | 役割 | 地点 | 画面操作 |
| :---: | :--- | :--- | :--- |
| 1 | START | 森林公園駅 北口 | 参加開始で自動付与 |
| 2 | GREENWAY | GREENWAY CAFÉ | QRから「スタンプを受け取る」 |
| 3 | TURN | 森林公園 南口 | QRから「スタンプを受け取る」 |
| 4 | GOAL | 森林公園駅 北口 | QRから「スタンプを受け取る」 |

- 参加開始前に中間地点QRを読むと、参加開始画面への案内が表示されます。
- 同じ地点は重複取得できません。
- `/stamps` の「デモチェックイン」は現地QRを使わないプレゼン用操作です。
- 4地点完了すると、デモコード `GREENBEAT-2027` を表示します。

#### 通知

- `/stamps` の「通知を設定」を選んだ場合のみ、ブラウザの許可ダイアログを表示します。
- 現行版は通知許可状態を保存するだけです。実際のプッシュ通知配信は未接続です。

### 3-5. PWA・オフライン

- ブラウザの「ホーム画面に追加」を使うと、アプリ形式で起動できます。
- 主要ページは先行キャッシュされます。
- 閲覧済みコンテンツの再利用は可能ですが、地図タイル等の外部通信データまでは保証しません。
- デモ開始前に各画面を一度開き、オフライン確認を行ってください。

## 4. 運営スタッフ向け操作

### 4-1. 運営コントロール

`http://localhost:3000/admin` を開きます。

変更は同じブラウザプロファイルで開いたタブ間へ同期されます。別端末、別ブラウザ、別プロファイル、プライベートウィンドウには同期されません。

#### 全体告知

1. 種別「ご案内」「注意」「緊急」を選びます。
2. メッセージを入力します。
3. 「配信する」を選びます。
4. 同じブラウザで来場者画面のバナーを確認します。
5. 解除するときは「停止」を選びます。

#### タイムテーブル

各プログラムを次から選択します。

- 予定どおり
- 遅延：10分、20分、30分
- 中止

変更後、同じブラウザの `/schedule` を再確認します。

#### スポット状況

各地点を次から選択します。

- 営業：営業中／一時休止／売切れ
- 混雑：空いている／やや混雑／混雑

変更後、同じブラウザの `/spots` と `/map` を再確認します。

#### デモ状態のリセット

画面最下部の「デモ状態をリセット」は、告知、運行状態、スポット状態を初期化します。来場者の参加ID、スタンプ、お気に入りは消しません。

全データを消す場合は、ブラウザのサイトデータ削除を使用します。実施前に確認してください。

### 4-2. 当日KPI

画面のKPIはすべて固定されたデモ値です。実参加者数や実クーポン利用数ではありません。

### 4-3. QRの掲示

1. `/qr-demo` をLAN公開URLまたは正式URLで開きます。
2. 各カードのURLが対象端末から接続可能か確認します。
3. ブラウザ印刷または作成済みPDFを使って掲示します。
4. START、GREENWAY、TURN、GOALの順と場所を確認して設置します。
5. 撮影・印刷後もQRに直接手書きでURLを書き換えないでください。

現行QRは、署名・当日期限・運営限定表示を環境変数で有効化できます(GBN-DEP-001 8章)。本番公開時は有効化し、**当日朝に印刷**してください。ローカルデモでは従来どおり無署名で動作します。

## 5. データ保存とプライバシー

| データ | 保存先 |
| :--- | :--- |
| 来場者参加ID・スタンプ・お気に入り・通知許可 | `green-beat-demo-engagement-v1` |
| 告知・運行・スポット状態・更新時刻 | `green-beat-demo-operations-v1` |

- いずれも端末ブラウザのlocalStorageです。サーバーへ送信・集約されません。
- ブラウザの閲覧データを削除すると保存情報が消えます。
- 端末の紛失、共有PC、画面共有には注意してください。
- 管理画面や運営状態は複数端末で共有されません。

## 7. トラブルシューティング

| 症状 | 原因 | 対処 |
| :--- | :--- | :--- |
| `localhost:3000` を開けない | 起動未完了、ポート競合、Docker停止 | Docker Desktopと起動ログを確認。必要に応じ再起動 |
| 初回起動が長い | npm依存関係の導入中 | 完了するまで待つ。ターミナル終了は避ける |
| QRをスマートフォンで読んでも開かない | QRが `localhost`、または別LAN | 表示PCのLAN IPでQR画面を開き直す |
| 「チェックポイントが見つかりません」 | URLの地点IDが無効 | `/qr-demo` の公式デモQRを使い直す |
| 「参加開始が必要です」 | 参加ID未発行 | `/join` で参加を開始してから再読取 |
| スタンプが消えた | ブラウザ、プロファイル、端末変更、サイトデータ削除 | 参加開始時と同じブラウザを使用。デモ値として再設定 |
| 管理変更が反映されない | 別端末・別プロファイル、保存エラー | 同じブラウザの別タブで確認し、サイトデータの保存可否を確認 |
| 地図が表示されない | ネットワーク、OpenStreetMap接続、拡張機能 | 通信とブラウザ設定を確認。ページ以外の表示でデモを継続 |
| 通知を有効にできない | ブラウザ非対応または拒否済み | サイト設定から通知を変更。実配信ではない点も説明 |
| オフライン画面が出る | 未訪問ページまたはキャッシュ未生成 | 通信復帰後に再読込し、事前に各画面を訪問 |

## 8. 制限事項

- `/admin` の認証は環境変数設定時のみ有効です。ローカルデモは認証なしで動作します(GBN-DEP-001 6章)。
- 運営データの端末間同期は `OPERATIONS_STORE` 設定時のみ有効です。ローカルデモは端末内保存です(GBN-DEP-001 7章)。
- KPIは固定デモ値です。
- QRの署名・期限・不正QR画面は `QR_SIGNING_KEYS` 設定時のみ有効です。ローカルデモは従来のデモURLです(GBN-DEP-001 8章)。
- 現地性ガード(現在地・順序・移動時間チェック、GBN-CNT-001 2-7)は `checkinGuard.enabled` 設定時のみ有効です。デモでは無効で、「デモチェックイン」ボタンが使用できます。
- プッシュ通知の実配信は未実装です。
- 地図中間座標、開催日、出演者、出店、特典は仮情報です。
- 個人情報や本番運営データを入力しないでください。
