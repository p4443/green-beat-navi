## 2. 負荷試験

### 2-1. 方法・環境

- ツール:autocannon
- 対象:本番ビルド(standalone・単一プロセス)、`OPERATIONS_STORE=memory`
- 環境:開発機上のDocker(※本番Cloud Runとは絶対値が異なるため傾向値として扱う)

### 2-2. 結果(エラー率はすべて0%)

| シナリオ | 並列 | 時間 | req/秒 | p50 | p99 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| ホーム `/` | 50 | 15秒 | 2,633 | 18ms | 40ms |
| 運営状態 GET `/api/operations`(来場者ポーリング相当) | 100 | 15秒 | 2,303 | 39ms | 73ms |
| 運営操作 POST `/api/operations` | 20 | 10秒 | 2,145 | 8ms | 19ms |

- **容量評価**:来場者は15秒間隔ポーリングのため、GET 2,300req/秒 ≒ **同時接続約3.4万人相当**を単一インスタンスで処理可能。想定規模(数百〜数千人)に対し十分な余裕。Cloud Run最大2インスタンス設定でさらに冗長。

## 4. 本番有効化時の確認方法(スモークチェック)

公開URLに対して次を実行すると、GBN-DEP-001 の各チェックリスト(ページ応答・セキュリティヘッダー・認証・同期・署名QR・現地性ガード)を自動判定します。

```bash
docker run --rm -v "$PWD":/app -w /app node:lts-alpine \
  node scripts/smoke-check.mjs https://公開URL
```

- ✅ PASS / ⚠️ WARN(本番推奨機能が未設定)/ ❌ FAIL(要対応)で表示。FAILがあると終了コード1
- 本報告書時点のローカル検証:PASS 14 / WARN 4(すべて「本番用機能が未設定」の想定どおりの警告)/ FAIL 0

### 本番公開後の推奨手順

1. GBN-DEP-001 2章でデプロイ → スモークチェック実行(WARNの内容を確認)
2. 6章(認証)→ 7章(同期)→ 8章(署名QR)を有効化し、都度スモークチェックで PASS 化を確認
3. 本番URLで負荷試験(2章と同コマンドでURLを差し替え)を1回実施し、傾向値と比較
4. イベント前に現地性ガードを有効化(GBN-CNT-001 2-7。実測座標の確定後)
