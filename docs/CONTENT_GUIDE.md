# GREEN BEAT NAVI コンテンツ編集ガイド

## スポット位置・演奏プログラム・開催場所の変更方法

- 文書番号:GBN-CNT-001
- 版:1.1
- 改訂日:2026年11月26日
- 対象:運営担当者・技術支援(エンジニアでなくても編集できます)

> アプリに表示される内容は **1つのファイル** `src/data/content.json` に集約されています。このファイルを編集して保存・コミットするだけで反映されます。編集ミスは自動チェック(Gitフック・CI)が検出してくれるので、壊す心配なく編集できます。

---

## 1. 編集できる内容と反映先

| content.json の場所 | 内容 | 反映される画面 |
| :--- | :--- | :--- |
| `eventSummary` | 開催日・開催場所・入場・主催の表示 | ホーム |
| `featuredPrograms` | 見どころ(タイトル・時刻・説明) | ホーム |
| `scheduleItems` | タイムテーブル(演奏曲・出演者・時刻・会場) | タイムテーブル、運営画面 |
| `eventSpots` | スポット(名前・説明・**位置座標**) | 会場マップ、お店とメニュー、運営画面 |
| `greenwayRoute` | コースのライン(座標の列) | 会場マップ |
| `mapCenter` | 地図を開いたときの中心位置 | 会場マップ |
| `stampCheckpoints` | スタンプ地点(QR連動・増減可) | スタンプ、QR一覧、チェックイン画面 |

## 2. よくある変更のやり方

### 2-1. 演奏曲・プログラムを変更する

`scheduleItems` の該当項目の `title`(曲目・プログラム名)、`participants`(出演者)、`time`/`endTime`(時刻)、`area`(会場)を書き換えます。

```json
{
  "id": "opening",
  "time": "09:30",
  "endTime": "10:00",
  "title": "Morning Green Session",
  "area": "木陰のアンサンブル",
  "participants": "サックス・アンサンブル",
  "kind": "music"
}
```

- 時刻は必ず `"09:30"` のような **2桁:2桁** で書きます。
- `kind` は `music`(演奏)/ `experience`(体験)/ `market`(マーケット)のいずれかです。
- プログラムを増やす場合は `{ ... }` のブロックごとコピーし、`id` を**新しい名前**(半角英数とハイフン)にします。

### 2-2. スポットの位置を変更する

`eventSpots` の該当スポットの `latitude`(緯度)と `longitude`(経度)を書き換えます。

**座標の調べ方(どちらでも可)**

- **Googleマップ**:地点を右クリック → 一番上に表示される座標をクリックするとコピーされます。1つ目の数字(36.xx)が `latitude`、2つ目(139.xx)が `longitude` です。
- **OpenStreetMap**:地点を右クリック →「住所を表示」→ 画面の検索欄に座標が表示されます。

実測で確定した座標にしたら、`coordinateStatus` を `"provisional"`(仮)から `"verified"`(確定)へ変えます。

### 2-3. 開催場所そのものを変更する(会場変更)

次の4点をセットで変更します。

1. `eventSummary.areaLabel` — ホームに出る場所の説明文
2. `mapCenter` — 新会場の中心座標
3. `greenwayRoute` — コースのライン。`[経度, 緯度]` の**順序に注意**(スポットとは逆順)。新ルートに沿って5〜15点ほど並べます
4. `eventSpots` — 各スポットの座標と名前

> スタンプ地点の増減は 2-5 を参照してください。**印刷済みQRがある場合は必ず再印刷**が必要です。

### 2-4. 開催日・主催表示を変更する

`eventSummary` の `dateLabel`(開催日)、`organizer`(主催)、`designatedManager`(指定管理者)を書き換えます。

### 2-5. スタンプ地点(QR連動)を増やす・減らす・変更する

`stampCheckpoints` を編集します。**並び順がそのまま来場者の回る順**になり、一番上の地点は参加開始時に自動付与されます。達成判定(クーポン表示)は地点数に自動で連動します。

```json
{
  "id": "greenway-cafe",
  "order": 2,
  "name": "GREENWAY CAFÉ",
  "role": "GREENWAY",
  "description": "緑道の音楽と地域の味を体験"
}
```

**増やすとき**

1. `{ ... }` ブロックをコピーして追加したい位置に挿入します。
2. `id` は新しい名前(半角小文字英数とハイフン。例:`music-stage`)にします。この id がQRのURL(`/checkin/music-stage`)になります。
3. 上から順に `order` を 1, 2, 3… と振り直します。
4. コミット後、`/qr-demo` に新しい地点のQRが自動で追加されるので、**全地点のQRを印刷し直して**掲示します。

**減らすとき**

1. 該当ブロックを削除し、`order` を振り直します。
2. 削除した地点の掲示QRを**必ず撤去**します(読み取っても「チェックポイントが見つかりません」と表示されます)。

**重要な注意**

| 注意 | 理由 |
| :--- | :--- |
| 印刷・掲示済みQRがある状態で `id` を変更しない | 旧QRが無効になります。名称変更は `name` の変更だけで済みます |
| イベント当日の増減は行わない | 参加中の来場者の達成判定が途中で変わってしまいます |
| 一番上は必ずスタート地点にする | 参加開始時に自動付与される地点です |
| 増減したら `/qr-demo` から全QRを再印刷 | 掲示物とアプリの不一致を防ぎます |

## 3. 編集時のルール

| ルール | 理由 |
| :--- | :--- |
| `id` は変更しない | お気に入り・運営状態・QRが `id` で紐づいています。変更すると来場者のデータが外れます |
| 文字は `"` で囲み、項目の間に `,` を忘れない | JSONの文法です。崩れると自動チェックが失敗します |
| 時刻は `"13:30"` 形式 | 自動チェックの対象です |
| 座標は 緯度=36.xx / 経度=139.xx 程度の値 | 取り違えると地図の表示が飛びます(自動チェックが検出します) |
| 個人情報(氏名・電話等)を書かない | 本アプリは個人情報を扱わない設計です(GBN-SEC-001 4章) |

## 4. 保存から公開までの流れ

1. `src/data/content.json` を編集して保存します。
2. GitKraken(またはコマンド)でコミットします。**このとき自動チェックが実行され、編集ミスがあれば具体的なメッセージ付きで止まります。**
3. push すると GitHub 上でも再チェック(CI)が実行されます。
4. チェックが通れば反映完了です(本番ホスティング導入後は自動デプロイされます)。

**手元で事前に確認したい場合**(任意):

```bash
docker run --rm -v "$PWD":/app -w /app node:lts-alpine npm test
docker compose up   # http://localhost:3000 で画面確認
```

---

## 5. エラーが出たとき

自動チェックのメッセージには **どの項目が・なぜ駄目か** が日本語で表示されます(例:`station-north-rotary: latitude(緯度)139.37 が不正です`)。

| 症状 | 原因と対処 |
| :--- | :--- |
| `JSON` や `Unexpected token` を含むエラー | カンマ・`"` の付け忘れ。直前に編集した行を確認 |
| `latitude/longitude が不正` | 緯度と経度の取り違え。36.xx と 139.xx を入れ替える |
| `time` 関連のエラー | `9:30` → `09:30` のように2桁にする |
| `id が重複` | コピーして増やした項目の `id` を新しい名前へ変更 |
| 解決しないとき | 変更を元に戻すか、技術支援(GBN-SEC-001 8-2章)へ連絡 |
